- **XcodeGen**: `brew install xcodegen`

## Quick Start

```bash
git clone <repository-url>
cd aretacare
cp backend/.env.example backend/.env
```

Edit `backend/.env` with your credentials (see README.md for full variable list).

Generate secret key:
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Two variables are easy to miss because the app starts without them:

- **`HCAPTCHA_SECRET_KEY`** — required for the web waitlist and unauthenticated feedback.
  Verification fails closed, so leaving it unset breaks signups while the app otherwise looks
  healthy. Get keys at https://www.hcaptcha.com/.
- **`REDIS_URL`** — backs shared rate-limit counters. Optional for local development (docker
  compose already runs Redis and falls back to per-process memory without it), but
  **required in any deploy running more than one instance**: without it each process keeps
  its own counters, so configured limits are silently multiplied by the instance count and
  reset on every deploy.

Optional settings, all with working defaults (see the comments in `backend/.env.example`):

| Variable | Default | Purpose |
|----------|---------|---------|
| `DB_POOL_SIZE`, `DB_MAX_OVERFLOW`, `DB_POOL_TIMEOUT` | 10 / 8 / 10 | Database connections per backend instance. Per-instance total × number of instances must stay under your Postgres connection limit |
| `REFRESH_TOKEN_STORE_RAW` | `TRUE` | Rolling-deploy compatibility for refresh tokens. Set `FALSE` once every instance runs the current release; only token hashes are stored from then on |
| `REFRESH_TOKEN_ROTATION_GRACE_SECONDS` | 30 | How long a just-rotated refresh token is still accepted |
| `REFRESH_REUSE_REVOKES_ALL` | `FALSE` | `TRUE` also revokes all of a user's sessions when a rotated refresh token is presented again |
| `ADMIN_REQUIRE_MFA` | `FALSE` | `TRUE` requires admin accounts to have MFA enabled |

Local development notes:

- The compose Postgres port is published on `127.0.0.1` only.
- `RESET_DB=true` (drop and recreate all tables at startup) is honoured only with `DEBUG=True` and a local database host; it is ignored anywhere else.

Start services:
```bash
docker compose up --build
```

Access: Frontend http://localhost:3001 | API http://localhost:8000/docs

Signed out, the frontend shows the marketing landing page. Sign in (or visit `/login`) to reach the chat.

### iOS App Setup (optional)

The `.xcodeproj` is tracked in git but generated by XcodeGen from `project.yml`. Regenerate after `project.yml` changes:

```bash
cd ios
xcodegen generate    # Generate Xcode project from project.yml
open AretaCare.xcodeproj
```

Configure `ios/AretaCare/Configuration/Debug.xcconfig`:
```
API_BASE_URL = http://localhost:8000/api
```

Build and run on iOS Simulator (requires Xcode 16+, iOS 17+ target). The Simulator works
without `Secrets.xcconfig`.

**Device and App Store builds additionally need `Secrets.xcconfig`** (gitignored):
```bash
cd ios/AretaCare/Configuration
cp Secrets.xcconfig.template Secrets.xcconfig
```
Then set `DEVELOPMENT_TEAM` to your Apple Team ID and `REVENUECAT_API_KEY` to your RevenueCat
API key. Without these the project builds for Simulator but cannot sign for a device.

**SPM Dependencies** (resolved automatically on first build):
- `KeychainAccess` >= 4.2.2 — secure token storage
- `MarkdownUI` >= 2.4.0 — markdown rendering
- `RevenueCat` >= 5.27.1 — subscriptions and paywall (iOS requires a subscription)
- `sentry-cocoa` — crash reporting; skipped at runtime when no DSN is configured

## AWS S3 Setup

### 1. Create Bucket
- AWS Console → S3 → Create bucket
- Enable "Block all public access"
- Choose your region

### 2. Configure CORS
Bucket → Permissions → CORS:
```json
[
    {
        "AllowedHeaders": ["*"],
        "AllowedMethods": ["GET", "PUT", "POST", "DELETE"],
        "AllowedOrigins": ["http://localhost:3001", "https://your-production-domain.com"],
        "ExposeHeaders": []
    }
]
```

### 3. Create IAM User
See [AWS_IAM_POLICY.md](AWS_IAM_POLICY.md) for policy and setup.

## Production Deployment (Render)

1. Push code to GitHub
2. Render dashboard → New → Blueprint → Connect repository
3. Render detects `render.yaml` automatically
4. Set environment variables:
   - Required: `OPENAI_API_KEY`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET_NAME`, `ADMIN_EMAILS`
   - Optional: `S3_KEY_PREFIX`, `WEBAUTHN_RP_ID`, `WEBAUTHN_ORIGIN`, `PUSH_NOTIFICATIONS_ENABLED`, `APNS_KEY_PATH`, `APNS_KEY_ID`, `APNS_TEAM_ID`
   - Talk mode (iOS live voice, off by default): `TALK_ENABLED=TRUE`, `REVENUECAT_SECRET_API_KEY` (RevenueCat → API keys → secret key) and `API_PUBLIC_URL` (the API's public base URL with `https://`, e.g. `https://api.aretacare.com` — OpenAI calls the assistant's tools there and does not follow an http→https redirect, which shows up as `Http status code: 400`). The backend refuses to start with Talk enabled and either one missing, or with a URL that doesn't start with `https://` (a bare host such as `api.aretacare.com` fails the same way as `http://`). **Cloudflare must let OpenAI's servers reach `POST /api/talk/mcp`**: bot protection that challenges non-browser clients answers OpenAI with a 403 challenge page, and the assistant then talks but cannot read or change anything (backend log: `live error code=responses_validation_failed … Error retrieving tool list from MCP server`). Add a WAF custom rule on each API hostname — `http.request.uri.path eq "/api/talk/mcp" and http.request.method eq "POST"` → Skip (bot protections / managed challenge). The endpoint authenticates every call with its per-call token.
   - Auto-configured: `DATABASE_URL`, `SECRET_KEY`, `CORS_ORIGINS`
   - Frontend (static site): `VITE_HCAPTCHA_SITE_KEY` is **required** — the production build fails without it
5. Update S3 CORS with Render frontend URL
6. Deploy

`render.yaml` sets `autoDeployTrigger: checksPass`, so a deploy starts only after the GitHub checks on the commit (`.github/workflows/ci.yml`: backend tests, frontend build, iOS build) have passed. The Postgres instance is declared with an empty IP allow list (private network only); add specific addresses there if you need to connect from outside Render.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Docker build fails | `docker system prune -a && docker compose up --build` |
| Database connection error | `docker compose logs db` then `docker compose restart db` |
| S3 Access Denied | Verify IAM policy and credentials |
| OpenAI quota error | Check billing at platform.openai.com |
| Frontend network error | Check `VITE_API_URL` and CORS settings |

## Backend Tests

The suite in `backend/tests` runs the real application against PostgreSQL with pgvector and makes no calls to OpenAI, S3 or SMTP. Setup and the run command are in [`backend/tests/README.md`](../backend/tests/README.md). CI runs the same suite on every pull request and push to `main`.

## Backend Dependencies

`backend/requirements.in` holds the top-level pins; `backend/requirements.txt` is a generated lockfile with hashes for every package and is what the images install (`pip install --require-hashes`). To change a dependency, edit `requirements.in`, run the `pip-compile` command shown at the top of that file (Linux, Python 3.11, the same as the production image), and commit both files. Test-only packages live in `backend/requirements-dev.txt`.

## Post-Deployment: Embedding Backfill

After deploying the semantic journal retrieval feature, backfill embeddings for existing journal entries:

```bash
# Call the admin endpoint to process a batch (repeat if remaining > 0)
curl -X POST "http://localhost:8000/api/admin/embeddings/backfill?batch_size=100" \
  -H "Authorization: Bearer <admin-token>"
```

New journal entries are automatically embedded on creation. The backfill is only needed once for pre-existing data.

## Testing Checklist

### Web
1. Register account (check email verification)
2. Test conversation interface
3. Upload document
4. Record audio
5. Generate daily digest
6. Share care session with collaborator
7. Enable MFA (Settings → Control Access)
8. Check admin console (if admin email configured)
9. Verify semantic retrieval (ask about a past journal topic, check AI references it)

### iOS
1. Login with existing account
2. Conversation: send message, verify markdown rendering, test edit/copy/reset context menu
3. Conversation (shared care session): verify collaborator messages appear within ~10s via polling
4. Attachments: take photo, choose photo, choose file — verify upload and document message
5. Journal: verify entries render with markdown, search, filter by type, expand/collapse
6. Documents: upload, search, edit category/description, preview PDF/image
7. Audio: record, verify transcription, play back from message bubble
8. Audio recordings: upload from Audio tab, verify journal synthesis triggers, edit category/summary
9. Daily digest: open Digest tab, verify markdown rendering; with a digest due (after 2 AM local time), verify one is generated shortly after the care session loads
10. Settings: rename care session, change color, care session statistics display, collaboration (share/revoke/invite)
11. Logout: verify push token unregistered before auth cleared (check backend logs)
12. Release build: verify `aps-environment: production` in entitlements, verify crash without `API_BASE_URL`
13. Talk (backend needs `TALK_ENABLED=TRUE`): first use shows the consent sheet, then the microphone prompt; ask about something in the Health Profile and something only in an old journal entry; dictate a journal entry and confirm it; ask to change a medication and find it under pending changes in Health Profile; interrupt the assistant mid-sentence; mute, talk (the assistant should not hear it), unmute; end the call and check that the summary card appears in Chat within a few seconds as "Saving…" and then fills in, and check the summary, the recording (both voices) and transcript in Audio Recordings, and the journal entries
14. Talk edge cases: airplane mode mid-call, an incoming phone call, locking the screen, a Bluetooth headset, AirPods stem press to mute and unmute (iOS plays its tone and the Mute button follows), speakerphone (no echo), Reduce Motion, largest Dynamic Type, VoiceOver

### iOS Pre-Deploy
- Replace `TEAMID` in `frontend/public/.well-known/apple-app-site-association` with your actual Apple Team ID
- Replace placeholder SSL pinning hashes in `ios/AretaCare/Core/Networking/CertificatePinningDelegate.swift` with actual production certificate public key hashes. Generate with:
  ```bash
  openssl s_client -connect aretacare.com:443 </dev/null 2>/dev/null | \
    openssl x509 -pubkey -noout | \
    openssl pkey -pubin -outform der | \
    openssl dgst -sha256 -binary | base64
  ```
